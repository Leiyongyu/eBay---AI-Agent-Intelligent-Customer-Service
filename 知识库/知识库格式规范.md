# 客服知识库：格式规范与上传流程

> 适用：eBay 客服 AI Agent 项目。整理知识的人或智能体都按本文件产出，产出的 Excel 可以直接在工作台上传。
> 最后更新：2026-11-09

## 一、流程

```
原始聊天记录（数据库 / 飞书导出）
   → 整理成「来源文件」（每批资料一个 Excel，放在 知识库/来源/）
   → 合并成「店铺上传文件」（每个店铺一个 Excel，放在 知识库/上传/）
   → 工作台「知识库」页：选店铺 → 选择 .xlsx 文件（自动校验预览：错误、警告、各站点 token）→ 确认替换
```

**重要：上传是按店铺整体替换。**每次提交后，这个店铺原来的全部知识都会下线，换成这份文件里的内容（旧版本保留，可在「历史版本」里回滚）。所以：

- 上传文件必须包含这个店铺的**全部**知识，不能只传新增的那一批；
- 新整理出一批知识时，把它的行追加到店铺上传文件里，再整份上传。

## 二、原始资料在哪里

| 资料 | 怎么拉取 | 保存位置 | 说明 |
|---|---|---|---|

读取某个店铺的买家会话可以用这条 SQL：

```sql
select c.id as conv, c.item_id, m.conversation_seq, m.sender_role, m.sent_at, m.body
from conversations c join messages m on m.conversation_id = c.id
where c.store_id = 'EBAY_STORE_1' and c.conversation_type = 'FROM_MEMBERS'
order by c.id, m.conversation_seq;
```

店铺回复正文末尾常带一串零宽字符（工具水印），整理时要去掉。

## 三、目录与文件命名

```
知识库/
├─ 知识库格式规范.md                      ← 本文件
├─ 来源/                                  ← 每批资料整理出的来源文件（同样是上传模板格式）
│   ├─ 人工补充.xlsx                       ← 人工口述/手写的知识都加在这一份里（长期维护，不按日期另存）
│   ├─ 飞书售后群_20261026.xlsx
│   ├─ EBAY_STORE_1_聊天记录_20261024.xlsx
│   └─ EBAY_STORE_1_聊天记录_20261024.md    ← 该批的整理说明、会话索引（可选）
└─ 上传/                                  ← 每个店铺一份，直接上传
    └─ EBAY_STORE_1_知识库_20261026.xlsx
```

- 来源文件：`<来源>_<资料截止日期 YYYYMMDD>.xlsx`，例如 `企微售后_20260331.xlsx`、`EBAY_STORE_2_聊天记录_20261101.xlsx`。
- **例外：`人工补充.xlsx`**——负责人口述或手写的知识（公司制度、流程、话术、发票税务等，不限主题）一律追加到这一份文件，长期维护、不按日期另存；
  编号用 `POL-` 前缀（按主题再分，如 `POL-INV-001` 发票、`POL-RET-001` 退货），同一条修改时编号不变。
  它和其他来源文件一样不能单独上传，要合并进店铺上传文件再整份上传。
- 上传文件：`<店铺ID>_知识库_<合并日期 YYYYMMDD>.xlsx`。每次合并另存一个新日期的文件，不要覆盖旧文件，方便对比。

## 四、Excel 格式（与工作台上传模板一致）

- 文件格式 `.xlsx`，工作表名必须是 **`知识条款`**（另一个工作表「填写说明」可有可无）。
- 第 1 行是表头，列按表头名识别，顺序可以调整。一行一条知识，最多 2000 行，文件不超过 10MB。
- 空白模板可以在工作台「知识库」页下载，也可以直接复制 `上传/` 里现有的文件改。

| 列 | 必填 | 填法 |
|---|---|---|
| 编号 | 建议填 | 字母、数字和 `- _ .`，最长 40 个字符；同一文件内不能重复。按第五节的前缀规则编号，更新时编号不变 |
| 标题 | 是 | 一句话概括这条知识 |
| 正文 | 是 | 完整内容，**不要重复标题**（系统会自动拼上）。条件、例外写在同一条里；建议不超过 600 字 |
| 适用站点 | 是 | `全部`，或 `EBAY_US` / `EBAY_DE` / `EBAY_GB`，多个用英文逗号分隔；只能填店铺已开通的站点，不确定就填 `全部` |
| 能否对买家说 | 是 | `可以`：AI 会据此回复买家；`仅内部`：只给审核员参考，AI 不会对买家说 |
| 主题 | 否 | 发货、物流、退货、退款、质保、适配、商品、价格、发票税务、订单、售后、合规、安装、话术模板、客服、其他（填别的按"其他"处理） |
| 优先级 | 否 | 1–99，数字越小越优先，条款冲突时以小的为准；默认 50。分档见第五节 |
| 语言 | 否 | 正文语言：`zh`、`en`、`de`，多语言模板填 `de,en`；默认 `zh` |
| 生效日期 | 否 | `YYYY-MM-DD`，默认上传当天 |
| 失效日期 | 否 | `YYYY-MM-DD`，留空表示长期有效（假日季政策之类要填） |
| 相关SKU | 否 | 多个用英文逗号分隔，写基础 SKU（去掉 `-YXR`/`-RXY`/`-YXQ`、`-AMZUS3` 等后缀），例如 `BMW-30046-0092,BMW-30047-0092` |
| 启用 | 否 | `是` / `否`；`否` 表示上传但暂不生效（存为草稿）。规则见第五节 |
| 负责人/来源 | 否 | 来源或维护人，**最长 64 个字**（超过会报错），例如 `飞书售后咨询群 2026-04至10`、`聊天记录整理(CONV 16)` |
| 适用场景 | 否 | 只对“仅内部”条款有用：会话属于这些场景时，会话页的「内部参考」卡片会列出这条给客服看。多个用英文逗号分隔，只能填：`适配`、`商品参数`、`质量问题`、`破损错发缺件`、`不适配`、`退货退款`、`物流异常`、`取消改地址`、`发票`、`评价`、`议价`、`常驻`（每个会话都显示，如店铺概况）。不填 = 只在知识库页查看。见第五节第 7 条 |
| 适用店铺 | 否 | 留空或 `全部` = 所有店铺；只给部分店铺时填店铺名（或店铺 ID），多个用英文逗号分隔。知识库页上传时选“上传到全部店铺”，每个店铺按这一列取自己的条款、各自生成一个新版本；同一个编号可以有多行（通用版 + 某店铺的特殊版），但适用店铺不能重叠 |
| 参考文档 | 否 | 引用的参考文档编号，如 `DOC-0001`，多个用英文逗号分隔。编号要先在知识库页「参考文档」页签上传文件后才有。知识库页条款列表、会话页「内部参考」里可以直接点开。见第五节第 8 条 |

## 五、填写规则

### 1. 编号前缀（新来源先在这里登记）

| 前缀 | 来源 | 示例 |
|---|---|---|
| `S1-` | EBAY_STORE_1 店铺买家聊天记录 | `S1-FIT-001` |
| `FS-SOP-` | 飞书售后群：内部处理流程 | `FS-SOP-008` |
| `FS-TS-` | 飞书售后群：按产品类型的排查说明 | `FS-TS-008` |
| `FS-SKU-` | 飞书售后群：按产品号的产品要点，后面接产品线-产品号 | `FS-SKU-BMW-30046` |
| `WX-` | 企业微信售后记录（待整理） | `WX-SOP-001` |
| `S2-`、`S3-`… | 以后新增的店铺，按店铺顺序编 | `S2-FAQ-001` |
| `CS-` | 全部店铺买家聊天记录整理出的通用条款（所有店铺共用）；`CS-PRF-<店铺ID>` 是各店铺概况 | `CS-ASV-001`、`CS-PRF-ZN-c9f83e498e35` |
| `POL-` | 人工补充的知识（公司制度、流程、话术等，人工口述或编写），统一放在 `来源/人工补充.xlsx` | `POL-RET-001`、`POL-INV-001` |

同一条知识更新内容时**编号不变**，上传预览会把它显示为"变更"；换编号会被当成删一条、加一条。

### 2. 能否对买家说

- 填 `可以`：事实、政策、排查步骤、回复模板，AI 可以直接转述给买家。
- 填 `仅内部`：供应商赔付/补发结论、索赔证据要求、退款比例上限、疑似骗货识别、违规做法警示、内部协作约定、店铺后台信息。
- 一条知识里两类内容都有的，拆成两条。

### 3. 优先级分档

| 优先级 | 用于 |
|---|---|
| 10 | 合规禁令（不得以利益换好评、不得引导站外联系等） |
| 20 | 公司通用流程和政策 |
| 30 | 店铺规则、店铺常见问题 |
| 40 | 产品类型的排查说明、回复模板 |
| 50 | 单个 SKU 的产品要点 |

### 4. 启用规则与 token 预算

AI 起草回复时，会把该店铺、该站点**所有已启用、可对买家说**的条款一次性放进提示词（全量注入）。上限由 `.env` 的 `KNOWLEDGE_FULL_CONTEXT_MAX_TOKENS` 控制，当前是 12000。**超过上限时，这个站点的所有消息都会转人工**，上传预览会提示每个站点的 token 数。

当前系统还**不会按会话的 SKU 过滤**条款，带 SKU 的条款一旦启用，每条消息都会注入。所以目前约定：

| 条款 | 启用 |
|---|---|
| 仅内部 | 是（不进 AI 提示词，不占预算） |
| 可以对买家说，且「相关SKU」为空 | 是（人工抽查后） |
| 可以对买家说，且「相关SKU」不为空 | **否**，等系统支持按 SKU 注入后再改为"是" |

每个站点已启用、可对买家说的条款合计要控制在 12000 token 以内（中文约 1 字 1 token），建议留出余量，不超过 8000。

### 5. 不能写进条款的内容

- 买家个人信息：姓名、用户名、邮箱、电话、地址、VIN、订单号、物流单号、税号。会话只用编号（如 `CONV 25`）引用。
- 站外联系方式（邮箱、电话、QQ、WhatsApp 等），以及引导买家站外交易的内容。
- 用退款、补发、折扣换好评或修改差评的内容；引导买家选择某个退货原因的内容。这类历史做法只能写成"仅内部"的禁止条款，正文里不要引用原话，避免 AI 照抄。
- 没有核实的承诺，例如"一定适配""即插即用"等，除非来源明确，且对应的是具体 SKU。
- 不确定的内容写上"（需人工确认）"，并在上传前确认。

### 6. 正文写法

- 一条只讲一件事：一个政策、一类问题，或一个产品号。
- 可以对买家说的条款写成可以直接转述的事实和步骤；需要人工决定的事项（退款金额、补发、编程能否免除等）写明"转人工"。
- 多语言回复模板在同一条里分段写，例如"德语：……"、"英语：……"；金额、日期、单号用 `{percent}`、`{date}`、`{tracking_no}` 这类占位符。

### 7. 仅内部条款怎么被用到（适用场景）

- “仅内部”的条款**不会进入 AI 的提示词**，AI 不知道它们的内容；AI 必须遵守的规矩要写进系统提示词或合规检查，写在这里不管用。
- 它们给客服、售后看：在「适用场景」里填了场景的，处理会话时会自动出现在会话页的「内部参考」卡片里。
- 会话属于哪个场景，系统按这个顺序判断：客服标的售后类型 → 售后群工单类别 → AI 识别的意图 → 会话阶段。
- 一张卡片最多列 10 条（按优先级），场景挂得太宽会把重要的挤掉，只挂真正要看的场景。
- 新写的内部流程、禁令、店铺信息，记得填适用场景；店铺概况填 `常驻`。

### 8. 怎么引用参考文档

- 报表、手册、供应商资料、物流手册等**文件**不要写成本机路径（如 `知识库/来源/xxx.xlsx`，同事在工作台里打不开），先在知识库页「参考文档」页签上传，得到编号 `DOC-0001`。
- 在条款的「参考文档」列填编号；正文里可以写“详表见 DOC-0001”。正文提到编号却没填这一列，上传时会提醒。
- 上传前检查：编号不存在或已删除 → 报错；文档已归档、“可以对买家说”的条款引用文档、引用敏感文档但条款的适用店铺超出文档范围 → 提醒。
- **文档只给人看**：AI 不读文档内容，也不会发给买家；AI 要用的知识仍然写进条款正文。
- 文档里不要留买家原话、地址、姓名、电话；必须保留的标为“敏感”（只有管理员能打开，其他人只看到标题）。
- 被当前条款引用的文档不能删除，先在 Excel 里去掉引用再上传；清空知识库不会删文档。

## 六、更新与下线

- **改内容**：在店铺上传文件里改对应行（编号不变），整份重新上传。
- **下线一条**：把「启用」改成"否"，或者删掉这一行，再整份上传。
- **新增一批**：把来源文件里的行追加到店铺上传文件（编号不能和已有的重复），另存为新日期的文件后上传。
- **传错了**：在工作台「知识库」页的「历史版本」里点「回滚到此版本」。

## 七、上传前自检

1. 工作表名是 `知识条款`，表头齐全；标题、正文、适用站点、能否对买家说都不为空。
2. 编号不重复，最长 40 个字符，前缀已在第五节登记。
3. 文件里包含这个店铺的全部知识，不只是新增的一批。
4. 带「相关SKU」的可以对买家说的条款，启用都是"否"。
5. 正文里没有个人信息和站外联系方式。
6. 在工作台选择文件后看自动生成的预览：错误必须为 0，各站点 token 不超过 12000，逐条看过警告后再点「确认替换」。
   - 例外："可能违反 eBay 规则"的警告如果是零件号被识别成电话号码（例如喷油器型号 `0445115007`），可以忽略。

## 八、交给整理智能体的任务模板

可以直接复制下面这段，改掉尖括号里的内容后发给智能体：

```
请把 <资料位置，例如：数据库 ebay_cs_agent 中 store_id='EBAY_STORE_2' 的买家会话 / data/feishu_kb/cases.jsonl>
整理成客服知识库，严格按「D:\JMH\项目\ebay客服AI Agent\知识库\知识库格式规范.md」执行：
1. 产出来源文件：知识库/来源/<来源>_<YYYYMMDD>.xlsx，工作表「知识条款」，13 列与规范一致；
2. 编号前缀用 <前缀>，按规范区分"可以/仅内部"，带 SKU 的可以对买家说的条款启用填"否"；
3. 去掉所有个人信息，历史回复中的违规做法只写成"仅内部"的禁止条款，不引用原话；
4. 再把它合并进 知识库/上传/<店铺ID>_知识库_<新日期>.xlsx（保留原有全部行，编号不重复）；
5. 用项目里的 backend/app/knowledge/excel_import.py 的 parse_workbook 校验（错误为 0），
   并报告各站点已启用、可对买家说的条款 token 数；
6. 最后用中文列出：新增多少条、需要人工确认的条目、发现的刊登错误或流程问题。
```
