# 参考文档库：开发方案

> 提出：业务负责人，2026-11-09。执行：开发工程师。
> 关联：知识库 Excel 上传（`backend/app/knowledge/excel_import.py`）、会话页“内部参考”（`knowledge/scenes.py`、`InternalRefsCard.vue`）。

## 一、背景与结论

### 1. 商品问题：能从 eBay 接口拿到准确数据的，AI 照常回复，不用改

现在 AI 回答商品问题已经是这样做的：

- 买家问当前商品的参数、OE 号、尺寸、包装内容、运费、发货时效、退货政策、有没有货时，AI 调 `get_item_details`，只按 eBay 刊登数据回答（`prompts/reply.md` 第 6 行）。
- 刊登和知识里都没有依据的问题，不凭常识回答，直接转人工（`reply.md` 第 16 行）。
- 产品手册类知识（FS-SKU 等单品条款）已在 2026-11-09 全部删除。

**这部分不改。**

### 2. 知识条款里引用的外部文件

问题出在 CS-ESC-001 这类条款：

- 条款是“仅内部”的，AI 看不到，回复用不到，对回复没有影响；
- 但正文里引用了本机文件 `知识库/来源/全店铺聊天记录_20261103_意图路由.xlsx`，同事在工作台里打不开。

**结论：新增一个“参考文档库”，可行。**

- 用途：专门存放第三方文件和内部资料，比如分析报表、供应商资料、操作手册 PDF、物流手册。
- 引用方式：知识条款用编号（如 `DOC-0001`）引用这些文档。
- 查看位置：客服在知识库页、会话页“内部参考”里可以直接点开。

## 二、范围

**要做：**

1. 文档库：上传、列表、搜索、预览/下载、替换新版本（保留旧版本）、归档、删除（被引用时不能删）。
2. 知识库 Excel 新增一列「参考文档」，填文档编号，上传时校验。
3. 显示引用的地方：
   - 知识库页的条款列表、上传预览；
   - 会话页“内部参考”卡片，每条条款下面显示它引用的文档，点开即看。
4. 权限、审计、首批数据（见第七节）。

**这一期不做：**

- **AI 不读文档内容。**文档不进提示词，不建向量，也不发给买家。原因：文档未经整理审核，且负责人规定知识由人整理后上传，见方案 v2.2 第 21.2 节“大模型用途”。
- 不做在线编辑、全文检索。
- 不在页面上单条新增或修改知识条款。知识条款仍然只能通过 Excel 整体替换来维护；页面上手动添加的只是文档。

## 三、数据模型

新表 `kb_documents`：参考文档。表和每个字段都要写中文注释，`tests/test_models.py` 会检查。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int 主键 | |
| doc_no | String(16)，唯一 | 引用编号 `DOC-0001`，自动递增，删除后不复用 |
| title | String(200) | 标题 |
| description | Text | 说明：这份文档是什么、什么时候用 |
| category | String(32) | 分类：报表 / 手册 / 供应商资料 / 物流 / 其他 |
| store_ids | JSON，可空 | 适用店铺；空表示全部店铺。非管理员只能看到自己负责店铺的文档 |
| sensitive | bool，默认 false | 含买家个人信息等敏感内容：只有管理员能下载，其他人只能看到标题 |
| status | String(16) | ACTIVE 使用中 / ARCHIVED 已归档（列表默认不显示，已有引用仍可打开） |
| version | int | 当前版本号，替换时加 1 |
| file_name / content_type / size / sha256 / stored_path | | 当前版本的原始文件名、类型、大小、哈希、存放路径（相对项目目录） |
| uploaded_by / uploaded_at / updated_at | | 上传人、上传时间、最后更新时间 |

新表 `kb_document_versions`：历史版本，字段为 `doc_id`、`version`、文件的 5 个字段、`uploaded_by`、`uploaded_at`。替换时，旧版本记录写到这里，旧文件保留不删。

`knowledge_chunks` 新增 `doc_refs`（JSON，可空）：这条条款引用的文档编号列表。启动时 `add_missing_columns` 会自动补上这一列。

### 文件存放

- 路径：`data/kb_documents/<doc_no>/v<版本>_<安全文件名>`。
- 新配置：
  - `KB_DOCS_DIR`：默认 `data/kb_documents`，写 D 盘项目目录下，不写 C 盘；
  - `KB_DOCS_MAX_MB`：默认 30。
- 允许的类型：pdf、docx、xlsx、xls、csv、pptx、md、txt、png、jpg、jpeg、webp。其他类型（含 zip、exe）拒绝。
- 病毒扫描：复用售后附件的扫描逻辑。本机 WinDefend 服务目前是停的，扫描结果记“未扫描”。**不要替用户改系统安全设置。**
- 不适用聊天记录 30 天保留，也不受“清理知识库”影响：清空知识库不删文档。

## 四、接口

全部挂在 `/internal` 下，需要登录。“管理员”指 `require_admin`。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/internal/kb-docs?q=&category=&status=` | 登录 | 列表。按负责店铺过滤；`sensitive` 的对非管理员只返回标题，不返回下载地址；附“被多少条当前条款引用” |
| POST | `/internal/kb-docs` | 管理员 | 上传。文件以 base64 放在 JSON 里（与知识库上传同一做法，不引入 multipart），同时提交元数据 |
| PUT | `/internal/kb-docs/{id}` | 管理员 | 改标题、说明、分类、适用店铺、敏感标记 |
| POST | `/internal/kb-docs/{id}/replace` | 管理员 | 上传新版本：编号不变，旧版本进历史 |
| POST | `/internal/kb-docs/{id}/archive`、`/restore` | 管理员 | 归档、恢复 |
| DELETE | `/internal/kb-docs/{id}` | 管理员 | 有当前条款（PUBLISHED / DRAFT）引用时返回 409，并列出引用它的店铺和条款编号；没有引用才删除，文件一并删除 |
| GET | `/internal/kb-docs/{id}/file?version=` | 登录 | 预览/下载。pdf、图片、txt、md 用 inline，其他用 attachment；越权一律 404；敏感文档只有管理员能下载 |
| GET | `/internal/kb-docs/{id}/refs` | 登录 | 哪些店铺的哪些条款引用了它 |

审计事件：`KB_DOC_UPLOADED`、`KB_DOC_REPLACED`、`KB_DOC_UPDATED`、`KB_DOC_ARCHIVED`、`KB_DOC_DELETED`、`KB_DOC_DOWNLOADED`。同一个人同一版本 10 分钟内重复打开只记一次。

## 五、知识库 Excel：新增「参考文档」列

- 加在现有 15 列之后（第 16 列）。同步修改：
  - `COLUMNS`；
  - 模板列宽 `widths`；
  - “填写说明”页；
  - 导出（`maintenance.export_rows`）。

  导出后原样再上传，预览必须显示内容不变。
- 填法：文档编号，多个用英文逗号分隔，例如 `DOC-0001,DOC-0003`。
- 校验：

  | 情况 | 处理 |
  |---|---|
  | 编号不存在或已删除 | 错误 |
  | 编号对应的文档已归档 | 提醒 |
  | “可以对买家说”的条款引用文档 | 提醒：AI 不会读文档，也不会发给买家 |
  | 引用了敏感文档，但条款的适用店铺超出文档的适用店铺 | 提醒 |

- 正文里写了 `DOC-\d{4}`，但这一列没填：提醒“正文提到了文档，请在「参考文档」列填写，才能点开”。
- 写库：`KnowledgeChunk.doc_refs`。内容哈希只在有引用时拼进去，做法与「适用场景」相同（`ParsedRow.content_hash`），这样加列前后上传不会把所有条款都显示成“变更”。

## 六、前端

1. **知识库页新增页签「参考文档」：**
   - 列表列：编号（可复制）、标题、分类、适用店铺、敏感、文件名、大小、版本、被引用条数、上传人与时间；
   - 搜索、分类筛选、显示已归档；
   - 管理员可以上传、编辑、替换、归档、删除；删除被拒时弹出引用清单；
   - 点标题：pdf、图片在新标签页预览，其他文件直接下载。
2. **知识库页的条款列表、上传预览：**加「参考文档」列，显示编号 + 标题，点开即看。
3. **会话页“内部参考”卡片（`InternalRefsCard.vue`）：**条款展开后，在正文下列出它引用的文档链接。接口 `/internal/conversations/{id}/internal-refs` 的每一条要多返回 `docs: [{doc_no, title, file_url | null}]`；敏感文档对非管理员，`file_url` 为 null，只显示标题。

## 八、测试（新增 `tests/test_kb_docs.py`）

1. **上传与列表：**
   - 编号递增；
   - 类型白名单、大小上限；
   - 文件名里带路径（`../`）要清理成安全文件名。
2. **权限：**
   - 非管理员不能上传、改、删；
   - 只看得到负责店铺的文档；
   - 敏感文档非管理员下载返回 403/404，列表里没有 `file_url`；
   - 越权访问返回 404。
3. **替换：**编号不变、版本加 1，历史版本可下载。
4. **删除：**有当前条款引用时返回 409 并列出引用；没有引用时可以删，文件也删掉。
5. **知识库 Excel：**
   - 「参考文档」列的错误和提醒（见第五节）；
   - 没填这一列的条款内容哈希不变；
   - 导出后原样再上传，预览全部“不变”；
   - 模板表头多一列（同时更新 `tests/test_knowledge_upload.py` 里的表头断言）。
6. **内部参考：**接口返回 `docs`，敏感文档对非管理员没有下载地址。
7. **AI 隔离：**生成草稿时，提示词里不出现文档内容。
8. **清理知识库：**“清空全部知识”后文档还在。

最后跑全量测试（目前 300 多条），并跑 `vue-tsc --noEmit`。

## 十、验收标准

1. 管理员在知识库页上传 DOC-0001，列表里能看到编号，点开能预览/下载。
2. 全部店铺上传的知识 Excel 里，CS-ESC-001 填了 `DOC-0001`：
   - 知识库页条款列表能点开 DOC-0001；
   - 会话页“内部参考”展开这条时能点开。
3. 客服账号：
   - 看得到自己负责店铺的文档；
   - 看不到别的店铺的文档；
   - 敏感文档只看得到标题。
4. 被引用的文档删除时会被拦住，并提示引用它的条款。
5. AI 草稿和提示词里没有文档内容（用一条会话核对生成依据）。
6. 全量测试通过，文档已同步。

## 十一、以后可以考虑（不在本期）

- 让 AI 检索文档内容：需要把文档转成文本、切段、建向量，并且只用人工审核过的文档。与“知识由人整理后上传”的规定有关，需负责人另行决定。
- 页面上单条新增、修改知识条款：与现在“按店铺整体替换、可回滚”的版本模型冲突，需要单独设计。
