# 物流问题处理手册

> **主题：物流**
> 适用：eBay 客服 AI Agent（审核工作台）的客服、售后、审核员
> 最后更新：2026-11-04（查件结果自动通知买家）
> 说明本系统遇到各种物流情况时，AI 自动做什么、人工要做什么、对买家怎么说。规则写在代码里（`backend/app/logistics/`），本文与代码保持一致；改规则时两边一起改。

---

## 一、总原则

1. **不给送达日期。**任何情况下都不对买家说预计哪天到、几天内到；送达时间以承运商为准（知识库 CS-SHP-002）。系统也不把谷仓、17TRACK 的预计送达日期交给 AI。
2. **只看“轨迹几天没更新”。**判断包裹是否有问题，只看最后一条轨迹距今多少天，不看承运商预计、不看下单多久。
3. **补发、退款由人工决定。**AI 不承诺补发、重发、换货、退款、赔偿；凡涉及补发的一律转人工。补发前先查库存，原发货仓没货只能协商退款。
   **以下都算“需判断补发”**（查物流和查件结果里出现都一样）：**损坏、丢件、退回、空包裹、轨迹未更新或长时间没更新**——转人工、会话标“物流问题需判断补发”、自动查补发库存。
4. **查件单提交后才算“已联系承运商”。**只有已在谷仓提交的查件单，AI 才能对买家说“我们已向承运商查询/催促”；系统起草的草稿、废弃的单都不算。
5. **谷仓回复是内部信息。**不原样转给买家，不向买家提“谷仓”“海外仓”“服务商”“查件单号”。

## 二、系统怎么判断

买家消息里提到物流（在哪、没收到、补发等）且查到订单时，AI 会调用“查包裹”工具，依次查：

1. **eBay 订单的发货记录**：承运商、跟踪号。
2. **谷仓出库单**（按 eBay 订单号查）：出库仓、物流方式、跟踪号（一票多箱每箱一个）、出库/揽收/妥投时间、商品 SKU。
3. **17TRACK 轨迹**：每个跟踪号注册一次（扣 1 单额度），之后免费查详情；全部节点按时间列出。

然后按下表给每个包裹一个“物流阶段”：

| 阶段 | 怎么判定 | 是否转人工 |
|---|---|---|
| 仓库处理中（NOT_SHIPPED） | 谷仓出库单是“待发货”，还没有跟踪号 | 否 |
| 正常运输中（OK） | 轨迹在更新，未满 4 天没动 | 否 |
| 已到取件点（PICKUP） | 17TRACK 状态“到达待取”（取件柜、ParcelShop、邮局） | 否 |
| 已签收（DELIVERED） | 17TRACK 状态“已签收” | 否；买家说没收到时转人工 |
| 轨迹多天未更新（STALLED） | 最后一条轨迹距今 ≥ 4 天；或有跟踪号但发货满 4 天仍查不到轨迹 | **是，需判断补发** |
| 长时间未更新（RESHIP_REVIEW） | 最后一条轨迹距今 ≥ 7 天；或发货满 7 天仍查不到轨迹 | **是，需判断补发** |
| 损坏/丢失/退回（LOST_DAMAGED） | 17TRACK 显示损坏、丢失、退件中、已退回、已销毁，或运输过久 | **是，需判断补发** |
| 物流异常（EXCEPTION） | 其他异常：投递失败、拒收、找不到收件人、地址错误、清关问题 | **是** |
| 查不到物流（NO_TRACKING / NO_INFO） | 没有跟踪号；或有跟踪号但刚发货（不满 4 天）还查不到 | **是**（人工核实） |
| 未开启轨迹查询（UNKNOWN） | 17TRACK 没开或没配置密钥 | 否（不做断更判断） |

- “最后一条轨迹”取 17TRACK 最新节点；没有节点时用谷仓揽收时间，再没有用谷仓出库时间（北京时间）或 eBay 发货时间。
- 4 天、7 天在 `.env` 的 `LOGISTICS_STALL_DAYS`、`LOGISTICS_RESHIP_DAYS` 调整。

**转人工时系统自动做的事：**

- 这条回复不自动发送，进待审核；
- 会话标成“待售后处理”：类型“物流问题需判断补发”（损坏、丢件、退回、空包裹、轨迹未更新/长时间没更新、买家要求补发）或“物流异常/未收到”（查不到物流、其他异常、已签收没收到），备注写承运商、跟踪号、几天没更新，标记人“AI（物流规则）”；会话已在待售后/处理中的不改；
- 符合条件的起草查件单（第四节）、查补发库存（第五节），结论追加到售后备注。

## 三、各种情况的处理方法

### 1. 买家只是问包裹到哪了（正常在途）

- **系统**：查到轨迹，阶段“正常运输中”，AI 正常起草回复。
- **对买家**：给出承运商和跟踪号，把全部轨迹按时间从早到晚逐条列出（时间、地点、状态），说明送达时间以承运商为准、可用跟踪号在承运商官网查看。不说“几天内到”。
- **人工**：审核后发送即可。
- 模板：知识库 CS-TPL-001 第一段（德语、英语）。

### 2. 订单还没发货（仓库处理中）

- **系统**：谷仓出库单状态“待发货”，阶段“仓库处理中”，不转人工。
- **对买家**：按 eBay 订单上承诺的最晚发货日回答“会在某日前发出”（只写日期）。
- **人工**：一般直接审核发送；如果已经超过最晚发货日还没出库，联系仓库核实。

### 3. 查不到物流信息

包括：订单没有跟踪号；有跟踪号但 17TRACK 查不到；刚发货承运商还没录入。

- **系统**：转人工，会话标“物流异常/未收到”。没有跟踪号时不会起草查件单（谷仓建单必须有跟踪号）。
- **对买家**：致歉，说明同事会尽快核实跟进；有跟踪号的给出跟踪号。不说“已联系承运商”。
- **人工**：
  1. 到谷仓后台核对出库单和跟踪号（是否还没出库、跟踪号是否录错、是不是不同承运商）；
  2. 刚出库 1–2 天查不到属正常，可回复买家稍后再查；
  3. 出库较久仍查不到，在谷仓后台建“无Ascan”查件单，或在本系统起草后提交（第四节）。

### 4. 轨迹 4 天以上没更新（断更）

- **系统**：转人工，会话标“物流问题需判断补发”，自动查补发库存写进备注；包裹是谷仓发的就起草一张“断更”查件单（发货后一直没有轨迹的优先“无Ascan”）（物流方式不支持时用“留言”），查件需求写好订单号、跟踪号、几天没更新和最后一条轨迹。
- **对买家**：致歉，给出跟踪号，说明同事会尽快跟进。查件单提交后再回复时才可以说“我们已向承运商查询”。
- **人工**：到“查件单”页 → 草稿待提交 → “修改并提交”，核对类型和查件需求后提交到谷仓；看谷仓答复和补发库存，决定补发还是协商退款（第五节）。
- 模板：CS-TPL-001 第二段；查件后用 CS-TPL-007。

### 5. 轨迹 7 天以上没更新（需判断补发）

- **系统**：同上起草“断更”查件单，会话标“物流问题需判断补发”，并自动查补发库存写进备注。
- **对买家**：同断更。不承诺补发或退款。
- **人工**：
  1. 先提交查件单，看谷仓/承运商答复；
  2. 决定是否补发：看售后备注或点“查补发库存”——原发货区域仓有货才能补发，没货只能协商退款（第五节）；
  3. 结果确定后再回复买家。

### 6. 包裹已到取件点（取件柜、ParcelShop、邮局）

- **怎么认出来**：轨迹最后是“Item arrived at Post Pick-Up Box”“ready for collection from a ParcelShop”之类，17TRACK 状态“到达待取”。这时轨迹本来就不会再更新，**不是断更**。
- **系统**：不转人工，不起草查件单。
- **对买家**：告诉买家包裹在哪个取件点等取件，请带上跟踪号尽快去取；取件点只保留有限时间，逾期会退回。
- **人工**：审核发送即可。如果之后轨迹变成“退回”，会按物流异常转人工。

### 7. 显示已签收，但买家说没收到

- **系统**：转人工（物流异常/未收到）；起草“妥投未收到”查件单（不支持时用“申请POD”或“留言”）；查补发库存写进备注。
- **对买家**：致歉，请买家看看邻居、信箱、门口、物业或包裹柜，有的承运商官网能查到送达照片；说明同事会与承运商核实。不承诺补发或退款（CS-SHP-005）。
- **人工**：
  1. 提交查件单，向谷仓要 POD（签收证明、送达照片）；
  2. 谷仓回复的附件会自动存进售后附件，查件单页可直接打开；
  3. 有 POD 且地址正确：把送达证明情况告诉买家，请再找找；没有 POD 或地址不对：按补发/退款流程处理。

### 8. 轨迹显示损坏、丢失、退回（需判断补发）

- **系统**：阶段“损坏/丢失/退回”，转人工，会话标“物流问题需判断补发”，自动查补发库存写进备注；不自动起草查件单（承运商已给出结果）。
- **对买家**：致歉，给出跟踪号，说明同事会尽快跟进。不下结论、不承诺补发或退款。
- **人工**：丢失、损坏：向承运商索赔，按库存给买家补发或协商退款；退回：建“退回原因”查件单问原因，退回后按补发/退款处理。

### 8.1 买家说收到的是空包裹（需判断补发）

- **怎么认出来**：买家消息里有 empty box / package was empty / leeres Paket / nichts drin / colis vide / 空包裹 / 空箱 等。
- **系统**：转人工，会话标“物流问题需判断补发”，自动查补发库存。
- **对买家**：致歉，请买家拍外包装和面单照片（FS-SOP-005：核对发货重量与外箱），说明同事会跟进。不承诺补发或退款。
- **人工**：核对出库重量、外箱是否完好，按补发/退款处理，必要时向承运商索赔。

### 8.2 其他物流异常：拒收、地址错误、无法投递、清关

- **系统**：阶段“物流异常”，转人工，会话标“物流异常/未收到”；起草查件单（“轨迹异常”多数物流方式不支持，会退到“断更”或“留言”）。
- **对买家**：致歉，给出跟踪号，说明同事会尽快跟进。不下结论（不说丢了、不说谁的责任）。
- **人工**：按具体原因处理——
  - 地址错误/找不到收件人：核对订单地址，必要时在谷仓建“改派”查件单；
  - 清关需补充资料：联系买家提供资料或缴费。
- 这些查件类型（改派、拦截、退回原因、查妥投地址）系统不会自动起草，需要人工在谷仓后台建。

### 9. 买家要求补发、重发、换货

- **怎么认出来**：买家消息里有 resend / replacement / Ersatz / neu senden / 补发 / 重发 等（德、英、法、意、西、中关键词）。
- **系统**：转人工，会话标“物流问题需判断补发”，查补发库存写进备注。轨迹正常时不起草查件单。
- **对买家**：说明已转同事处理，不承诺补发。
- **人工**：按第五节判断。

### 10. 买家要改收货地址

- 只能按 eBay 订单上的地址发货，卖家不能改订单地址（CS-SHP-006）。
- **未发货**：请买家在 eBay 订单里申请取消，退款后用正确地址重新下单。
- **已发货**：无法改地址，可以请买家联系承运商申请改派（以承运商为准）；必要时人工在谷仓建“改派”查件单。

### 11. 买家要加急、指定日期送达、问几天能到

- 物流商不提供次日达、指定日期或加急；付款后按刊登页写的处理时间发货，哪天送达取决于承运商，无法保证（CS-SHP-002、CS-TPL-005）。
- 买家急用时如实说明，由买家决定是否下单。

### 12. 一个订单有多个包裹

- 每个跟踪号单独查轨迹、单独判断；AI 回复里逐个包裹列出。任一包裹需要人工就转人工，查件单按包裹分别起草。

### 12.1 订单发货后通知买家（发货通知）

- **系统**：每小时汇总所有店铺当天（北京时间）在 eBay 标记已发货的订单，按站点语言写好订单号、承运商、跟踪号和承运商官网（请买家自己在官网输入跟踪号查询），放在顶部导航“发货通知”的“待审核”里；有取消申请或退款的自动标“不发”。不写送达日期。
- **人工**：每天在“发货通知”页过一遍当天的单，可以修改内容、点“不发”，勾选后“发送选中”。买家已有会话就发在会话里，没有的按订单新建会话（目前为模拟发送）。
- **注意**：eBay 标记发货时仓库多半只是打好面单，买家刚收到时可能还查不到轨迹，属正常。

### 13. 不是谷仓发的货

- 谷仓查不到出库单的订单（如其他仓发货），照常查 eBay 跟踪号的轨迹和判断，但**不会起草查件单**，也查不到补发库存，需人工在对应仓库/承运商处理。

### 14. 17TRACK 没开或额度用完

- 没开启时阶段为“未开启轨迹查询”，AI 只给承运商和跟踪号，不做断更判断。
- 每天新注册跟踪号有上限（`TRACK17_REGISTER_DAILY_LIMIT`，默认 50），超过的当天只给基本信息；剩余额度在“系统状态”页查看。

## 四、查件单（催货）

### 1. 起草

以下情况，且包裹是谷仓发的（有出库单号和跟踪号），系统自动起草查件单：

| 情况 | 优先选的查件类型（按物流方式支持的依次取） |
|---|---|
| 轨迹 ≥ 4 天未更新 / ≥ 7 天未更新 | 断更 → 留言 |
| 已签收但买家说没收到 | 妥投未收到 → 申请POD → 留言 |
| 轨迹异常 | 轨迹异常 → 断更 → 留言 |

- 草稿**只存在本系统**（单号 `DRAFT-` 开头），不发到谷仓；
- 同一订单或同一跟踪号已有未完结的查件单（谷仓状态不是“已完结”“废弃”）就不再起草；
- 开关：`.env` 的 `LOGISTICS_TICKET_AUTO_DRAFT`；通知邮箱：`LOGISTICS_TICKET_NOTIFY_EMAILS`（谷仓必填）。

### 2. 提交

- 顶部导航“查件单” → “草稿待提交”，或会话右侧“谷仓查件单”面板 → **修改并提交**；
- 弹窗里可改查件类型（只列这单物流方式支持的）和查件需求（中文，5–300 字），可“保存修改”“提交到谷仓”“废弃”；
- 提交后在谷仓正式建单，单号换成谷仓的 `CJ…`，记下提交人；建错的（例如包裹其实在取件点）点废弃，不会发到谷仓。
- 在谷仓后台手动建的查件单（包括谷仓后台保存的草稿）也会每天同步进来；谷仓后台的草稿只能在谷仓后台提交。

### 3. 谷仓回复后自动通知买家

- 每小时（`LOGISTICS_TICKET_SYNC_INTERVAL_MINUTES`）同步一次最近 30 天的查件单，包括在谷仓后台手动建的；也可在“系统状态”页点“立即同步”；
- 按 eBay 订单号匹配回店铺和买家；回复附件（多为 POD 签收照片）**一律下载**进售后附件，查件单页“谷仓已回复”里能直接看到缩略图；
- 最近 3 天有新回复的，AI 按买家语言起草一条通知（不提谷仓和单号，不给日期不承诺，有附件时说明已附上签收证明）：
  - **不需要人工的：自动连同附件发给买家**（`LOGISTICS_TICKET_AUTO_SEND`，目前为模拟发送，记在本系统会话里）。买家没来过信的，系统按订单新建一个会话再发；
  - **需要人工的不发**，标“需人工，未发送”并把会话标成待售后：查件类型是妥投未收到、退回原因、拦截、改派、查妥投地址；或回复里提到赔付、地址、拒收、无法派送等。
    回复里提到**丢失、遗失、退回、退件、破损、损坏、销毁、空包/空箱、未更新、久未更新、断更、无轨迹、补发**的，属于需判断补发：会话标“物流问题需判断补发”，并自动附上补发库存；合规检查不通过的也不发；
- 每张查件单在“谷仓已回复”的“发给买家”一列显示结果：已发给买家（含时间）/ 需人工，未发送 / 发送失败 / 找不到买家；每张只发一次。
- 需人工的：打开会话，在右侧“谷仓查件单”里把 AI 起草的消息填入回复框，修改后发送，再点“已处理”。

### 4. 查件类型支持情况

谷仓共 13 种查件类型：1 妥投未收到、2 断更、3 无Ascan、4 查自取地址、5 渠道联系电话、6 拦截、7 改派、8 申请POD、9 退回原因、10 催派、11 查妥投地址、12 轨迹异常、13 留言。

- 常用的 17 个物流方式都支持：妥投未收到、断更、无Ascan、退回原因；申请POD 除 FEDEX_ECON 外都支持；
- 常用的 17 个物流方式都**不支持**：催派、查妥投地址、轨迹异常（所以“轨迹异常”实际多退到“断更”）。

## 五、补发与退款

1. **补发由人工决定**，AI 不对买家承诺。
2. **补发前先查库存**：售后备注里已写好，或在查件单页点“查补发库存”（实时查谷仓）：
   - 看订单商品在**原发货区域仓**（如德国区）的可售数量，够就“可以补发”；
   - 不够就“不能补发，只能协商退款”，同时列出其他仓的库存供参考。
3. **SKU 对应**：谷仓出库单里的商品 SKU 就是谷仓 SKU（`JMH-` 开头）；用 eBay 订单 SKU 查时要把产品线前缀换成 `JMH`，如 `BWM-50016-0101` → `JMH-50016-0101`（系统会自动换，并去掉 `ZMY-DE-` 这类别名前缀和 `-AMZUS3` 后缀）。
4. 补发后仍有问题的不再补发，按售后处理（FS-SOP-008）。

## 六、每天的人工流程

1. 打开顶部导航 **“查件单”**：
   - **草稿待提交**：逐张“修改并提交”，建错的废弃；
   - **谷仓已回复**：看“发给买家”一列，确认每张查件结果都已自动发出；标“需人工，未发送”或“发送失败”的要处理；
   - **有新回复待回买家**：点“打开会话”，在右侧把 AI 起草的回复填入回复框，审核后发送，点“已处理”；
   - **需人工**：按查件结果处理，涉及补发的先查库存。
2. 打开 **“审核工作台”** → 筛选 **“待售后处理”**：处理 AI 按物流规则标记的会话（备注里有原因、跟踪号、未更新天数、查件单和库存结论）。
3. 回复买家时，AI 草稿写得不合适可以直接在输入框下方的**中文对照**里改中文，正式回复会自动译成买家语言。

## 七、配置项（`.env`）

| 配置 | 当前值 | 作用 |
|---|---|---|
| `LOGISTICS_STALL_DAYS` | 4 | 轨迹几天没更新算断更、转人工 |
| `LOGISTICS_RESHIP_DAYS` | 7 | 轨迹几天没更新标“需判断补发” |
| `LOGISTICS_TICKET_AUTO_DRAFT` | true | 是否自动起草查件单（只存本系统） |
| `LOGISTICS_TICKET_NOTIFY_EMAILS` | 已填 | 查件单通知邮箱（谷仓必填，最多 10 个） |
| `LOGISTICS_TICKET_SYNC_INTERVAL_MINUTES` | 60 | 每隔多少分钟同步一次查件单（0 = 只按下一项每天一次） |
| `LOGISTICS_TICKET_AUTO_SEND` | true | 谷仓回复后自动把查件结果和附件发给买家（目前模拟发送；需人工的不发） |
| `LOGISTICS_TICKET_SYNC_TIME` | 10:00 | 间隔设为 0 时，每天几点同步 |
| `LOGISTICS_TICKET_SYNC_DAYS` | 30 | 同步最近多少天创建的查件单 |
| `TRACK17_ENABLED` | true | 是否用 17TRACK 查轨迹 |
| `TRACK17_REGISTER_DAILY_LIMIT` | 50 | 每天最多新注册多少个跟踪号（每个扣 1 单） |

改完 `.env` 要重启 `main.py`。
